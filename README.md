# Nail Studio

React + TypeScript + Three.js 美甲编辑器。画稿以十个独立指甲保存，浏览器本地运行，无需后端服务。

## 启动

```sh
npm ci
npm run dev
```

`npm run build` 执行 TypeScript 检查并生成 `dist`；`npm run preview` 预览构建产物。

## 使用

底胶和法式素材以椭圆色样展示。粉色、紫色底胶在渲染时裁去左右各 8%、上下各 3%；法式胶裁去上方 27%、下方 23%、左侧 14%、右侧 29%，只取中间颜色区域。素材缩略图、2D、3D 纹理与导出 PNG 使用相同裁切范围，原始图片保留。

- 点击底部指甲缩略图选择编辑对象。甲型和长度对十指生效，底胶与图层默认只修改当前指甲。
- 顶部“清空”一次移除十指的底胶素材及全部法式、波点、饰品、上传图片与擦除记录，恢复白色空白甲面，保留当前甲型和长度；可通过撤销恢复。
- 法式：法式始终只有一个图层；设置颜色、覆盖比例、微笑线弧度或选择胶体素材都会替换当前法式，素材库第一个“无”会移除法式。
- 波点：波点始终只有一个图层；在 2D 画布点击或拖动绘制、或生成均匀波点都会复用该图层，重新生成时替换其点阵配置。
- 橡皮擦：先选择可见的法式或波点图层，再拖动擦除；只影响该图层，不破坏下方图层或底胶。饰品、上传图片及 3D 附件不可擦除；旧项目中图片图层的擦除记录也不再参与渲染。
- 饰品、上传图片：点击素材添加图层，选择图层后在画布拖动移动，使用属性面板缩放、旋转或精确定位。越过甲面轮廓的区域自动隐藏。
- 3D 附件：在编辑器左侧选择“3D 附件”，可添加蝴蝶结、小猫、花朵、爱心。支持 2D 拖动、位置/尺寸/旋转/颜色调整、隐藏、复制、删除及撤销；项目保存和十指复制包含附件。2D 和 PNG 显示模型俯视图，3D 使用实体网格，按甲面交点和法线贴附。附件中心限制在甲面内，实体边缘可伸出甲面；橡皮擦不作用于实体附件。
- 图层支持显示、隐藏、排序、复制和删除。可将底胶或完整画稿复制到十指。
- 每次笔画或拖动计为一次撤销操作；支持 Cmd/Ctrl Z、Cmd/Ctrl Shift Z。
- 3D 预览平铺两排十指，拖动旋转、滚轮缩放、点击选指、双击重置视角。
- 设计自动保存到当前浏览器的 localStorage。保存项目文件导出可再次打开的 JSON（包括上传图片）；PNG 导出当前指甲的透明背景画稿。

## 2D 与 3D 如何保持一致

`src/model.ts` 从 `src/nail-masks.json` 读取 150 个模型的实测尺寸。六个形状族分别共用一张标准遮罩，按各手指的实际宽高缩放。甲根在上、甲尖在下；原始 X/Z 平面正交投影为画布平面。

标准轮廓来自真实 STL 全部三角面的离线投影并集，不是凸包。分析全部 150 个模型后，共享遮罩与每个模型的归一化面积重合率均超过 99.75%；详细方法、误差和尺寸规律见 [分析报告](docs/mask-analysis.md)。画稿宽 512 像素，高度按实测比例计算。3D 使用原始 STL，纹理 UV 与离线投影使用相同坐标，Canvas 顶部对应 UV 的 V=1。

`src/design.ts` 是共用画稿合成器：底胶 → 有序平面图层 → 每层擦除遮罩 → STL 轮廓裁切。2D 展示额外合成立体附件的俯视图；3D CanvasTexture 仅包含平面画稿，附件作为独立实体网格加载，避免重复贴图。切换甲型、长度时，图层使用相对坐标重新投影，不丢失画稿。2D 为便于编辑保持附件俯视方向，3D 根据贴附位置的甲面法线倾斜，透视和光照效果会不同。

`src/useEditor.ts` 管理撤销历史、本地保存、模型加载取消和画稿缓存。`src/assets.json` 收录现有 198 张图片；新增图片后应更新该目录索引。

## 加载性能

- 基础 2D 编辑不下载指甲 STL，也不运行 `projectMask`。六张标准 PNG 总共约 329 KiB，同族共享已解码图像，最近六组尺寸的五指画布使用内存缓存。
- 打开 3D 附件库或恢复含附件的项目时加载 `public/stl-models`。附件在 Worker 中统一朝向、归一化并通过顶点聚类简化高面数网格；会话内共享几何和俯视缩略图，不改写源 STL。首次加载蝴蝶结需要下载约 72 MiB。
- 仅进入 3D 时加载预览模块与原始 STL，逐个更新五指进度。解析、顶点坐标变换、UV 和法线计算放入 `src/stl.worker.ts`。
- 选手指不再重新加载模型；切换甲型、长度或离开 3D 时取消旧请求并释放几何内存。
- STL 使用 Cache API 持久缓存最近 15 个文件，内存保留最近 8 个。请求 URL 包含源文件 SHA-256 的版本片段，重新生成索引后自动失效。Worker 使用缓存副本，转移数据不会破坏原缓存。

## 重新生成轮廓

已有生成结果提交在项目中，正常运行或构建不需要 Python。修改源 STL 后执行：

```sh
python3 -m pip install numpy pillow
python3 scripts/prepare-masks.py
npm run build
```

脚本读取全部 150 个文件，生成 `public/nail-masks/` 六张遮罩、`src/nail-masks.json` 尺寸索引，以及 `docs/mask-analysis.json` 和对比图。要求每个共享轮廓的最差 IoU ≥ 99.5%，否则报错，需要重新评估模板。`docs/mask-analysis.md` 是本批模型的人工分析说明，替换源模型后也应更新。

## 当前边界

- “饰品素材”使用图片贴图；“3D 附件”使用四个 STL 实体。实体之间不自动避让或融合，图层顺序用于 2D 合成，3D 遮挡由空间位置决定；这是设计预览，不是可直接打印的合并模型。
- 左右手分别保存画稿，但复用同一套五指 STL。长度列表只显示实际存在的款式，包括方圆形儿童款；尖形没有短款。
- 自动保存属于单机浏览器存储，没有账号、云端同步或服务器数据库。大图片达到存储额度时会显示失败提示，请导出 JSON 备份。
- STL 素材约 1 GB，首次打开某款 3D 仍需下载五个文件。共享遮罩属于经过验证的近似，边缘存在细微误差，精度受标准遮罩和 512 像素画稿限制。
- 需要支持 Canvas 2D 的现代浏览器；3D 预览和立体附件俯视图生成还需要 WebGL。没有 WebGL 时仍可使用不含立体附件的 2D 编辑。
